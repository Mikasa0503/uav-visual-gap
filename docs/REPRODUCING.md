# Reproducing code checks and experiment evidence

## Supported reference

The tested stack is Linux x86_64, Python 3.8, PyTorch 2.1.0 with CUDA 12.1,
PyTorch3D 0.7.5, the official Warp 1.0.0 wheel, Isaac Gym Preview 4, and Aerial
Gym 2.0.1. A compatible NVIDIA driver and a licensed Isaac Gym distribution are
required for simulator execution. The film renderer is CPU-side and has separate
Blender/FFmpeg requirements documented in [REPLAY.md](REPLAY.md).

## Fresh source setup

1. Check out the project source. The current Git history contains older
   machine-specific operational records and has not been prepared as a public
   release history. Do not push or redistribute that history as-is. A sanitized
   source snapshot and a history rewrite require a separate review.
2. On a clean checkout, run `./scripts/prepare_aerial_gym.sh` to fetch the pinned
   Aerial Gym source. Install Isaac Gym Preview 4 under ignored `third_party/`;
   obtain it under its license because it is not included here. The helper
   refuses to replace an existing unverified copy. See
   [THIRD_PARTY.md](THIRD_PARTY.md).
3. Create the tested Conda layer and install the pinned Python layer:

   ```bash
   conda create --name uav_gap --file configs/conda-linux-64.explicit.lock
   conda activate uav_gap
   ./scripts/install_runtime.sh
   scripts/run.sh scripts/check_runtime.py --write-inventory
   ```

   `configs/conda-linux-64.explicit.lock` is the Linux-64 explicit Conda package
   list. `requirements-runtime.txt` pins direct pip dependencies;
   `configs/runtime-constraints.txt` prevents pip from silently changing the
   tested Torch/NumPy/network stack. `requirements-installed.txt` is a captured
   version inventory, not an installer input. The inventory generated by the
   runtime checker is written to ignored `runs/runtime_inventory.json`.
4. Run CPU tests:

   ```bash
   scripts/run.sh -m pytest -q
   ```

   This checks task logic and policy/data boundaries but does not initialize the
   simulator GPU or reproduce any flight score.

## Simulator smoke and GPU admission

The following command creates a simulator and CUDA context. First confirm that
no other GPU process is running and that at least 32 GiB is free; the runtime
also performs an admission check and monitors device memory while the job is
running:

```bash
scripts/run.sh scripts/smoke_aerialgym.py --num-envs 2 --steps 100
```

The smoke report is infrastructure evidence only. Never terminate another
user's GPU process to make room. The monitor is sampled and cannot guarantee
protection from a sudden external allocation.

## Reproducing model scores

A code checkout alone does not contain the checkpoints, datasets, manifests,
traces or exact per-episode summaries that support the scores in
[RESULTS.md](RESULTS.md). Transfer the matching artifact set into the project-local
ignored directories, verify its hashes, and use the protocol/configuration named
in each experiment. Formal training and evaluation commands are specified in
[FORMAL_PROTOCOL.md](FORMAL_PROTOCOL.md), [VISUAL_TRAINING.md](VISUAL_TRAINING.md)
and each saved run manifest. The formal multi-seed and final-test acceptance
gates are still open; reproducing a pilot validation is not a formal completion.

The rendered film has its own source trace, caption, font and encoder
provenance. Follow [REPLAY.md](REPLAY.md); do not infer policy performance from
a rendered clip alone.
